## Prerequisites

{% stepsBlock %}

- Node 22 or newer, and npm.
- A `package.json` with `"type": "module"` and Eleventy scripts:
  ```json
  {
  	"name": "baseline-quickstart",
  	"type": "module",
  	"scripts": {
  		"start": "rimraf dist/ && npx @11ty/eleventy --serve",
  		"build": "rimraf dist/ && cross-env ELEVENTY_ENV=production npx @11ty/eleventy"
  	}
  }
  ```
- Optionally a `.env` for environment-specific values. Skip it if you would rather set them in your npm scripts or your host:
  ```text
  ELEVENTY_ENV="development"
  BASELINE_URL="http://localhost:8080/"
  ```
  Baseline reads `ELEVENTY_ENV` itself, to decide what to enable in development versus production. `BASELINE_URL` it never sees: the settings file below hands it to Baseline as `settings.url`, which is the one place everything absolute is anchored. The name is yours to pick, though [[deployment-url-checks | deployment URL checks]] names two that are already taken. The other entries you might add are project-specific.

  Loading that file is your job, not Baseline's. If you keep one, install `dotenv` and import it at the top of whichever file reads the values, which is `src/_data/settings.js` here. Without a `.env` you need neither.

{% endstepsBlock %}

## 1) Install

```bash
mkdir baseline-quickstart
cd baseline-quickstart
npm init -y
npm install @11ty/eleventy @apleasantview/eleventy-plugin-baseline
npm install dotenv # only if you keep a .env
```

---

## 2) Configure

Create `eleventy.config.js` at the project root:

```js
import baseline, { config as baselineConfig } from '@apleasantview/eleventy-plugin-baseline';
import settings from './src/_data/settings.js';

export default async function (eleventyConfig) {
	await eleventyConfig.addPlugin(
		baseline(settings, {
			sitemap: true,
			navigator: true
		})
	);
}

export const config = baselineConfig;
```

Two things to notice:

{% stepsBlock %}

- `baseline()` takes two arguments. `settings` is the site identity (title, url, languages, head extras), written once in `src/_data/settings.js` and imported here; `options` is runtime behaviour (which modules are on, log verbosity, per-module options). Key by key, that is [[site-settings | site settings]] and the [[plugin-entrypoint | plugin entrypoint]]; why the two are apart is on the [[concept-overview | concept overview]].
- The `config` re-export looks unusual. It is. That way both Baseline and Eleventy agree on where things live (`src/` as input, `dist/` as output, the asset and public folders). Why a plugin cannot set those for you is on the [[concept-overview | concept overview]]; the contract it ships is the [[config-export | config-export reference]]'s.

{% endstepsBlock %}

## 3) Project files

Create the rest of the project files:

{% stepsBlock %}

- `src/_data/settings.js`: site identity (`title`, `url`, `defaultLanguage`, `languages`, `head` extras). This is the file the config imports, and living in `src/_data/` also hands it to your templates as `settings`.
  ```js
  import 'dotenv/config';

  export default {
  	title: 'My Site',
  	url: process.env.BASELINE_URL,
  	defaultLanguage: 'en'
  };
  ```
- `src/_includes/layouts/base.njk`: base layout. Drop `<baseline-head></baseline-head>` in place of the `<head>` element. That **placeholder** is the one element you write yourself.
- `src/content/pages/index.md`: a starter page with front matter and a body.
- `src/assets/assets.11tydata.js`, `src/assets/css/index.css`, `src/assets/js/index.js`: asset entry points (one CSS, one JS).
- `src/static/`: passthrough-copied to the site root. The on-disk folder is `static/`; the virtual directory key Baseline registers is `public`.

{% endstepsBlock %}

## 4) Run and build

{% stepsBlock %}

- Development:
  ```bash
  npm start
  ```
  Open http://localhost:8080/. Check `dist/` for output, including `dist/sitemap.xml`.
- Production build. `BASELINE_URL` is the address the build claims as its own, so point it at the real one before shipping. For this exercise any absolute URL does the job, `https://www.example.com/` included. Then run:
  ```bash
  npm run build
  ```
  Inspect `dist/` for the final files, and check that the canonical link and `dist/sitemap.xml` both carry the URL you set. Set `BASELINE_URL` back to `http://localhost:8080/` before returning to `npm start`.

  Leaving it unset is valid too: Baseline warns once at startup and omits the canonical rather than publishing a guess.

{% endstepsBlock %}

The **drafts preprocessor** (a build-time filter that drops templates marked `draft: true`) is on automatically. Drafts render while the dev server is running (`npm start`) and are dropped from a build (`npm run build`). The switch is Eleventy's own run mode rather than `ELEVENTY_ENV`, so any build drops them, production or not. The two variables are put side by side on [[project-structure | project structure]].
