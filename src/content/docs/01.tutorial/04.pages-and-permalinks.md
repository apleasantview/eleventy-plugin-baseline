Time to put something in `src/content/pages/`. Two things, in fact: a homepage and one page next to it, which is roughly what a fresh install of any content system hands you and for the same reason. One page can't show you how pages relate to each other.

Before either of them, a short detour into where their URLs come from.

---

## Decide how URLs are made

Eleventy lets every page declare its own address through a `permalink` in the front matter. That works, and it means every page you ever write has to remember to do it. A directory data file sets a rule once for everything in the folder instead, so you write the interesting part and the URL follows.

Create `src/content/pages/pages.11tydata.js`. The name matters: `pages.11tydata.js` inside `pages/` is how Eleventy knows this data belongs to that folder.

```js
export default {
	// Ensure we have a value to work with by explicitly asking for the slug field.
	permalink: function ({ slug, page }) {
		if (!slug) {
			console.warn(`Warning: No slug found for ${page.inputPath}`);
			return false;
		}

		try {
			const normalizeSlug = this.slugify(slug);
			return `/${normalizeSlug}/`;
		} catch (error) {
			console.error(`Error generating permalink for ${page.inputPath}:`, error);
			return false;
		}
	}
};
```

The rule is: a page's `slug` becomes its URL. Write `slug: 'about'` and the page lands at `/about/`. This is a Baseline convention rather than an Eleventy requirement, and the reason to adopt it is that a slug is a name while a permalink is a path. Names are easier to keep tidy.

The rest of the function is manners. `this.slugify` cleans up whatever you typed, so `'About Us'` still arrives as `/about-us/`. A page with no slug at all gets a warning and `return false`, which tells Eleventy not to write the file: a page with no name is more likely a mistake than a decision, and a loud nothing beats a quiet file at a URL you didn't choose.

{% alertBlock %}

It would be tempting to use `eleventyComputed` for creating the permalink, but that would always take precedence over the front matter field if set. The permalink function does plenty, including still allowing us to overwrite the field if needed.

{% endalertBlock %}

That last part is the escape hatch, and the next file uses it immediately.

## Write the homepage

Create `src/content/pages/index.md`:

{% raw %}

```md
---
title: 'Hello Baseline'
description: 'A minimal Eleventy page powered by eleventy-plugin-baseline.'
permalink: '/'
---

You are looking at a page rendered with Eleventy and the Baseline plugin defaults.

## Index

<ul class="index-links">
{% for item in collections.all %}
<li><a href="{{ item.url }}">{{ item.data.title }}</a></li>
{% endfor %}
</ul>
```

{% endraw %}

The homepage is the one page that can't follow the rule, because its address isn't derived from anything: it's the root. So it sets `permalink` in its front matter and the function steps aside, which is exactly the override the alert above promised.

`title` and `description` are doing more than they look like they're doing. Between them they fill the `<title>` tag, the meta description, the link preview when someone shares the page, and the structured data Baseline emits. Two lines of front matter, five outputs, no template work. It's worth writing them properly even here.

The loop at the bottom walks `collections.all`, Eleventy's collection of every page in the site. Right now that is one page listing itself, which is not much of a demonstration.

## Write a second page

Create `src/content/pages/about.md`:

```md
---
title: 'About'
slug: 'about'
description: 'What this site is, in one sentence, for anyone who wonders.'
---

A site built while following the Baseline tutorial. It has two pages, and this
is the second one.
```

No permalink, so the rule applies: `slug: 'about'` lands the page at `/about/`. That is the whole difference between these two files, and it's the thing worth noticing. The homepage names its address because it has to. Every other page you write from here just gets a name.

Reload the index and the loop has two entries.

## Have a look at it

There is enough now to see something:

```bash
npm start
```

Open http://localhost:8080/. You'll find your words, in the browser's default font, with no styling and nothing around them. That is not a mistake. Nothing has told Eleventy what a page should look like yet, so it renders your Markdown and stops.
