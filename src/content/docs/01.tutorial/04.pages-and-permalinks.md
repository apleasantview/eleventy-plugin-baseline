Time to put something in `src/content/pages/`. Two things, in fact: a homepage and one page next to it, which is roughly what a fresh install of any content system hands you, and for the same reason. One page cannot show you how pages relate to each other.

Before either of them, a short detour into where their addresses come from.

---

## Decide how URLs are made

Eleventy lets every page declare its own address: put a `permalink` in the front matter and be done with it. It also means remembering it every single time, and missing it once puts the page at whatever the filename happened to be. So we set a rule for the whole folder instead, and let the URLs follow from what each page is called.

That rule lives in a directory data file, and the name is the mechanism: `pages.11tydata.js` sitting inside `pages/` is how Eleventy knows this data belongs to everything in that folder. Create `src/content/pages/pages.11tydata.js`:

```js
export default {
	// Ensure we have a value to work with by explicitly asking for the slug field.
	permalink: function ({ slug, page }) {
		if (!slug) {
			console.warn(`Warning: No slug found for ${page.inputPath}`);
			return false;
		}

		try {
			const normalizeSlug = this.slugify(slug);
			return `/${normalizeSlug}/`;
		} catch (error) {
			console.error(`Error generating permalink for ${page.inputPath}:`, error);
			return false;
		}
	}
};
```

A page's `slug` becomes its URL. Write `slug: 'about'`, get `/about/`. This is a Baseline convention rather than an Eleventy requirement. A slug is a name, a permalink is a path, and names are easier to keep tidy.

The rest is manners. `this.slugify` cleans up whatever you typed, so `'About Us'` still arrives at `/about-us/`. A page with no slug gets a warning and `return false`, which tells Eleventy not to write the file at all: a page with no name is more likely a mistake than a decision, and a loud nothing beats a quiet file at an address you never chose.

{% alertBlock %}

It would be tempting to use `eleventyComputed` for creating the permalink, but that would always take precedence over the front matter field if set. The permalink function does plenty, including still allowing us to overwrite the field if needed.

{% endalertBlock %}

That last part is the escape hatch, and the next file needs it immediately.

## Write the homepage

The homepage is the one page that cannot follow the rule, because its address is not derived from anything. It is the root. Create `src/content/pages/index.md`:

{% raw %}

```md
---
title: 'Hello Baseline'
description: 'A minimal Eleventy page powered by eleventy-plugin-baseline.'
permalink: '/'
---

You are looking at a page rendered with Eleventy and the Baseline plugin defaults.

## Index

<ul class="index-links">
{% for item in collections.all %}
<li><a href="{{ item.url }}">{{ item.data.title }}</a></li>
{% endfor %}
</ul>
```

{% endraw %}

So it sets `permalink` in its front matter and the function steps aside. That is the override the alert just promised, used one file later.

`title` and `description` are quietly doing more than they look like they are doing. Between them they fill the `<title>` tag, the meta description, the preview card when someone shares the page, and the structured data Baseline emits. Two lines of front matter, five outputs, no template work.

The loop at the bottom walks `collections.all`, which is Eleventy's collection of every page on the site. Right now that is one page listing itself. Not much of a demonstration.

## Write a second page

Create `src/content/pages/about.md`:

```md
---
title: 'About'
slug: 'about'
description: 'What this site is, in one sentence, for anyone who wonders.'
---

A site built while following the Baseline tutorial. It has two pages, and this
is the second one.
```

No permalink, so the rule applies and `slug: 'about'` lands the page at `/about/`. That is the entire difference between these two files. The homepage names its own address because it has to, and every other page you write from here just gets a name.

Reload the index and the loop has two entries.

## Have a look at it

There is enough now to see something:

```bash
npm start
```

Open http://localhost:8080/. You will find your words, in the browser's default font, with nothing around them and nothing styling them. That is not a mistake. Nothing has told Eleventy what a page should look like yet, so it renders your Markdown and stops.

The shell those words belong in is the next page.
