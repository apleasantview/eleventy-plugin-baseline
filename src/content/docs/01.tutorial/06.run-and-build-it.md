You have run `npm start` twice already, so the dev server is not news. What is worth a page is the difference between that and a build, because the two are not the same site and the gap between them is where surprises live.

---

## The dev server

```bash
npm start
```

It serves on http://localhost:8080/ and rebuilds whenever you save. It also writes to `dist/` as it goes, so you can open the generated files while the server is running and see what your Markdown became.

{% alertBlock "info" %}

Eleventy never empties `dist/` for you. That is why both scripts run `rimraf` first: a file you deleted a week ago will otherwise still be sitting there, still being served, looking entirely convincing.

{% endalertBlock %}

---

## Build it for production

```bash
URL=https://www.example.com/ npm run build
```

Three things change. Your CSS is minified, because `ELEVENTY_ENV=production` is set by the `build` script and Baseline's PostCSS config turns on `cssnano` when it sees it. The navigator page, a development-only introspection page you have not met yet, is left out for the same reason. And any page marked `draft: true` in its front matter is dropped, this time because Eleventy itself knows it is doing a build rather than serving.

The `URL` in front of the command is the interesting part. Everything absolute Baseline emits, the canonical link on every page and every entry in the sitemap, is anchored to that value. A build without a real origin produces a site that quietly tells search engines it lives on your laptop. Setting it for the one command beats editing `.env` and having to remember to undo it. On a real deployment your host sets `URL` and you never think about it again.

{% alertBlock "info" %}

The `NAME=value` prefix works in bash and zsh. Windows `cmd` and PowerShell don't take it, which is what `cross-env` is for. It is already installed, and it belongs inside the `build` script in `package.json` rather than typed at the prompt.

{% endalertBlock %}

## Read what came out

Open `dist/`. Three things are worth looking at before you close the folder.

`dist/index.html`, and specifically its `<head>`. You never wrote one. Everything in there came from your front matter and your settings file, sorted and deduplicated on the way out.

`dist/sitemap.xml`, which nobody asked for. The sitemap module is on by default, it lists the pages you wrote, and the URLs start with the origin you passed rather than `localhost`. If they say localhost, the `URL` did not reach the build.

`dist/assets/css/index.css`, now on one line. That is the minification, and it is the visible proof that `ELEVENTY_ENV` did its job.

Everything past this point is deployment, which has enough of its own things to check that it gets [[deployment-url-checks | its own guide]].
