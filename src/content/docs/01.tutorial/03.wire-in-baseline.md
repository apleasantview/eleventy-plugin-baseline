Two files, neither of them long. Each one is shaped by a decision Baseline already made, and knowing which decision keeps the shapes from looking arbitrary later.

---

## Add the plugin

The config file is short, and its last line is the strangest thing in the whole tutorial. Create `eleventy.config.js` in the project root:

```js
import baseline, { config as baselineConfig } from '@apleasantview/eleventy-plugin-baseline';
import settings from './src/_data/settings.js';

/** @param {import("@11ty/eleventy").UserConfig} eleventyConfig */
export default async function (eleventyConfig) {
	await eleventyConfig.addPlugin(baseline(settings));
}

export const config = baselineConfig;
```

`baseline()` takes two arguments: `settings`, which is what your site *is*, and `options`, which is how Baseline *behaves*. Here you pass settings only, which leaves every option at its default: `sitemap` on, `multilingual` off, `navigator` on in development and off in production. That is the set this tutorial wants.

Now that last line. Eleventy has already chosen its directories by the time a plugin loads, so Baseline ships them as a separate export and asks you to forward it. That one line is what makes `src/` the input, `dist/` the output, and the folders you laid out on the last page findable by name. Leave it off and Baseline still runs, badly, in a project it cannot see.

Why Baseline has two configuration surfaces rather than one is the [[concept-overview | concept overview]]'s job; the contract that last line forwards is the [[config-export | config export reference]]'s.

## Give the site its identity

Next, the file `eleventy.config.js` just imported. Create `src/_data/settings.js`:

```js
import 'dotenv/config';

export default {
	title: 'Simple Baseline Site',
	tagline: 'Hello, Eleventy + Baseline',
	url: process.env.BASELINE_URL,
	defaultLanguage: 'en',
	noindex: false,

	head: {
		link: [{ rel: 'stylesheet', href: '/assets/css/index.css' }],
		script: [{ src: '/assets/js/index.js', defer: true }],
		meta: [{ name: 'color-scheme', content: 'light dark' }]
	}
};
```

It sits in `src/_data/`, so Eleventy picks it up as global data as well, and every template can read `settings.title` without importing anything. The layout you write two pages from now leans on that. Why the location is the part that matters is on [[project-structure | project structure]].

What belongs in here is identity, the things that would still be true if you rewrote every template tomorrow. `title` and `tagline` both feed the `<title>` tag, the tagline turning up on the homepage where there is no page title to lead with. `defaultLanguage` sets the `lang` attribute, and `noindex` is the site-wide switch for keeping a staging build out of search results. It is off here because this site is imaginary and nobody is looking for it. There are more keys than these, and the [[site-settings | settings reference]] has them all.

The `head` block is how tags reach every page. `link`, `script` and `meta` are arrays, and each entry's keys become the attributes on the rendered tag. They arrive alongside what Baseline emits anyway, which the [[head | head module]] lists in full. One stylesheet, one script, one colour-scheme hint is enough to start with; the two files those paths point at get written two pages from now.

{% alertBlock "info" %}

Baseline compiles your CSS and JS, but it does not link them for you. A bundle that is not listed here gets built and then never loaded, which looks exactly like the stylesheet not working.

{% endalertBlock %}
