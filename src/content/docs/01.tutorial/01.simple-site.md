Let's start by creating the project folder and `cd` into it:

```bash
mkdir simple-baseline-site
cd simple-baseline-site
```

Everything after this happens in there.

---

## Add the package file

Now the folder can become a project. Generate a standard `package.json` file:

```bash
npm init -y
```

Then switch `"type"` to `"module"`, which tells Node that the `.js` files here are ES modules, and add the two scripts the rest of the tutorial needs.

```diff-json
{
	"name": "simple-baseline-site",
	"version": "1.0.0",
	"scripts": {
-		"test": "echo \"Error: no test specified\" && exit 1"
+		"start": "rimraf dist/ && npx @11ty/eleventy --serve",
+		"build": "rimraf dist/ && cross-env ELEVENTY_ENV=production npx @11ty/eleventy"
	},
	"license": "ISC",
-	"type": "commonjs"
+	"type": "module"
}
```

`npm init` writes a handful of other keys as well, `description`, `main`, `keywords` and `author`. Leave them where they are; nothing in this tutorial reads any of them. `type` it writes for you, at the bottom of the file rather than the top, which is why it is worth scrolling for rather than adding.

Baseline is ESM, and so is the config you are about to write. Without that line Node reads `eleventy.config.js` as a CommonJS file and stops at the first `import`.

Both scripts lean on two small helpers, installed in the last step on this page.

---

## Install the packages

```bash
npm install @11ty/eleventy # Eleventy itself
npm install rimraf cross-env # the two script helpers
npm install @apleasantview/eleventy-plugin-baseline # and Baseline itself
```

Eleventy comes first: Baseline names it as a peer dependency, so it belongs in your `package.json` rather than inside the plugin. Then the two helpers the scripts lean on, `rimraf` to delete `dist/` and `cross-env` to set environment variables, both of them the same way on every operating system. Baseline comes last, and brings everything else it needs with it, including the image library it uses when you reach for images.

Nothing runs yet. There is no config telling Eleventy about Baseline, and nothing to render. Both arrive next.

---

## Keep the generated files out of git

If you are tracking this in git, add a `.gitignore` at the project root. Not using git? Skip the file. Nothing else in the tutorial depends on it.

```text
node_modules/
dist/
temp/
.env
```

`node_modules/`, `dist/` and `.env` are the usual suspects: two are rebuilt from what you commit, and the third arrives on the next page holding the values that differ between your laptop and the live site. `temp/` is a bonus folder to put stuff in.

---

## Tell it where it lives

One value in that file changes depending on where the site is running, which is why `url` reads from the environment instead of being typed in. Create a `.env` in the project root:

```text
ELEVENTY_ENV="development"
BASELINE_URL="http://localhost:8080/"
```

A `.env` file does not load itself, so install the package that does it:

```bash
npm install dotenv
```

That is the line at the top of `settings.js`. It sits in that file rather than in the config on purpose: the file that reads an environment variable is the one that should load the environment, and then it works whatever imported it, in whatever order. Baseline itself does not need the package. The `.env` does, and a project that sets its variables in npm scripts or on its host wants neither.

`BASELINE_URL` becomes `settings.url`, and `settings.url` is the only place Baseline looks when it needs an absolute URL. Localhost is the honest answer while you are working on your laptop; the value starts to matter when you build for production, two pages from now.

Leave it unset and Baseline says so at startup, then leaves the canonical links out rather than publishing one it had to guess. No claim beats a wrong claim. Everything else it anchors is listed in [[site-settings | site settings]].

`ELEVENTY_ENV` is the development-versus-production switch, and what it actually changes is on [[project-structure | project structure]], next to the Eleventy variable it is easy to confuse it with. On a deployed site both variables come from your host rather than from this file, which is why the file stays out of git.

Eleventy will start now. It will also render nothing at all, because there is still no content. That is the next page.
