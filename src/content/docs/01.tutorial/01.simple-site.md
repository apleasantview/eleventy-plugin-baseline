Let's start by creating the project folder. Everything after this happens in there.

```bash
mkdir simple-baseline-site
cd simple-baseline-site
```

---

## Add the package file

Generate a standard `package.json` file. Now the folder becomes a project.

```bash
npm init -y
```

Then switch `"type"` to `"module"`, which tells Node that the `.js` files here are ES modules, and swap the placeholder `test` script for the two the rest of the tutorial needs.

```json
{
	"name": "simple-baseline-site",
	"version": "1.0.0",
	"description": "",
	"main": "index.js",
	"scripts": {
		"start": "rimraf dist/ && cross-env ELEVENTY_ENV=development BASELINE_URL=http://localhost:8080/ npx @11ty/eleventy --serve",
		"build": "rimraf dist/ && cross-env ELEVENTY_ENV=production npx @11ty/eleventy"
	},
	"keywords": [],
	"author": "",
	"license": "ISC",
	"type": "module"
}
```

The whole file, so you can check yours against it. `npm init` wrote the empty `description`, `main`, `keywords` and `author`; nothing in this tutorial reads any of them.

Baseline is ESM, and so is the config you are about to write. Without that line Node reads `eleventy.config.js` as a CommonJS file and stops at the first `import`.

The two variables in those scripts change with where the site is running, so they get set per command rather than typed into a file. `BASELINE_URL` comes back two pages from now as `settings.url`; [[deployment-url-checks | deployment URL checks]] covers both of them.

Both scripts lean on two small helpers, installed in the next step.

---

## Install the packages

```bash
npm install @11ty/eleventy # Eleventy itself
npm install rimraf cross-env # the two script helpers
npm install @apleasantview/eleventy-plugin-baseline # and Baseline itself
```

Eleventy comes first: Baseline names it as a peer dependency, so it belongs in your `package.json` rather than inside the plugin. Then the two helpers the scripts lean on, `rimraf` to delete `dist/` and `cross-env` to set environment variables, both of them the same way on every operating system.

That last part is the whole reason they are here rather than in the shell. Baseline comes last, and brings everything else it needs with it, including the image library it uses when you reach for images.

Newer npm versions hold install scripts back until you approve them, so you may see a warning naming `sharp` and `esbuild`. Nothing in this tutorial needs either, so you can just ignore it.

---

## Keep the generated files out of git

If you are tracking this in git, add a `.gitignore` at the project root. Not using git? Skip the file. Nothing else in the tutorial depends on it.

```text
node_modules/
dist/
.cache/
temp/
```

`node_modules/` and `dist/` are the usual suspects, both rebuilt from what you commit. `.cache/` is where Baseline keeps the content graph it builds each run, which is derived from your pages.

`temp/` is a bonus folder to put stuff in.

Eleventy will start now. It will also render nothing at all, because there is still no content.
