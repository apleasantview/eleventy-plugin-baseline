Your pages render, and they arrive with nothing around them: no `<head>`, no navigation, no styling. This page gives them a shell and something to look at. It is also where two things you set up earlier finally connect to a file.

---

## Write the layout

Create `src/_includes/layouts/base.njk`:

{% raw %}

```nunjucks
<!DOCTYPE html>
<html lang="{{ settings.defaultLanguage }}">
	<baseline-head></baseline-head>
	<body>
		<main id="main">
			<h1>{{ title }}</h1>
			{{ content | safe }}
			{% if page.url !== "/" %}
				<p><a href="/">Back to the index</a></p>
			{% endif %}
		</main>
	</body>
</html>
```

{% endraw %}

The interesting line is the one that looks wrong. `<baseline-head></baseline-head>` is not a tag that goes inside the head; it *is* the head. Baseline replaces the whole element at build time with a real `<head>` containing the charset, the viewport, the title composed from your page and site titles, the meta description, the canonical link, the robots directives, and the extras you listed in `settings.head`. That is why it sits as a sibling of `<body>` rather than wrapping anything, and why you never write a `<title>` yourself. If you find yourself hand-writing a head tag, something has gone sideways.

The `lang` attribute reads `settings.defaultLanguage`, which is that same settings file from two pages ago turning up in a template. You didn't import it. Living in `src/_data/` is what does that.

`{% raw %}{{ content | safe }}{% endraw %}` is where the rendered Markdown of each page lands, and `safe` tells Nunjucks it is already HTML and shouldn't be escaped.

---

## Point the pages at it

The layout exists, and nothing uses it yet. Open `src/content/pages/pages.11tydata.js` and add one key above the permalink function:

```js
export default {
	layout: 'layouts/base.njk',

	permalink: function ({ slug, page }) {
		// unchanged
	}
};
```

Same reasoning as the permalink rule: it belongs to the folder, not to each page. Every page under `pages/` now renders into the layout, and any single page can still override it by setting its own `layout` in front matter. Set it once, forget it, break the rule where you need to.

Restart the dev server and look again. The words are the same, but there is a document around them now, and a title in the browser tab you didn't write.

---

## Add the stylesheet

Two entry points, one for CSS and one for JS, both named `index`. Baseline compiles those and nothing else, which sounds restrictive until you notice that `@import` and `import` still reach everything else.

Before the files themselves, one small piece of housekeeping. Create `src/assets/assets.11tydata.js`:

```js
export default {
	eleventyExcludeFromCollections: true
};
```

Baseline registers CSS and JS as template formats so it can compile them, which technically makes them pages. Without this file they turn up in `collections.all`, which means `index.css` would appear in the list of links on your homepage. One line, one folder, problem gone.

Now `src/assets/css/index.css`:

```css
body {
	font-family: system-ui, sans-serif;
	margin: 0;
	padding: 2rem;
	line-height: 1.5;
	color: #1f2937;
	background: #f8fafc;
}

h1 {
	margin-bottom: 0.5rem;
}
```

And `src/assets/js/index.js`, which the site does not need but the settings file has been promising since page three:

```js
document.addEventListener('DOMContentLoaded', () => {
	console.log('Howdy!');
});
```

Both compile to `dist/assets/`, mirroring the folders they came from, so `src/assets/css/index.css` is served at `/assets/css/index.css`. That is the path already sitting in `settings.head.link`, which is why the stylesheet loads without you adding a `<link>` anywhere. Compiling and loading are two separate jobs, and Baseline only does the first.

Reload once more and the page has a face.

The site is finished, in the sense that everything it needs now exists. What is left is knowing what happens when you run it for real.
