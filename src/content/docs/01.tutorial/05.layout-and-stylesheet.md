Your pages render, and they arrive with nothing around them: no `<head>`, no navigation, nothing to look at. This page gives them a shell. It is also where two things you set up earlier finally reach a file.

---

## Write the layout

One line in here is going to look wrong. Leave it alone, it is the point of the page. Create `src/_includes/layouts/base.njk`:

{% raw %}

```nunjucks
<!DOCTYPE html>
<html lang="{{ settings.defaultLanguage }}">
	<baseline-head></baseline-head>
	<body>
		<main id="main">
			<h1>{{ title }}</h1>
			{{ content | safe }}
			{% if page.url !== "/" %}
				<p><a href="/">Back to the index</a></p>
			{% endif %}
		</main>
	</body>
</html>
```

{% endraw %}

`<baseline-head></baseline-head>` is not a tag that goes inside the head. It *is* the head. Baseline replaces the whole element at build time with a real `<head>`: charset, viewport, the title composed from your page and site titles, the meta description, the canonical link, the robots directives, and whatever you listed in `settings.head`. That is why it sits as a sibling of `<body>` rather than wrapping anything, and why you never write a `<title>` yourself. If you catch yourself hand-writing a head tag, something has gone sideways.

The `lang` attribute reads `settings.defaultLanguage`, which is that same settings file from two pages ago turning up in a template. You did not import it. Living in `src/_data/` is what does that.

`{% raw %}{{ content | safe }}{% endraw %}` is where each page's rendered Markdown lands. `safe` tells Nunjucks it is already HTML and should not be escaped.

---

## Point the pages at it

The layout exists and nothing is using it. One key fixes that, and it goes in the file you wrote last page rather than in every page you will ever write:

```js
export default {
	layout: 'layouts/base.njk',

	permalink: function ({ slug, page }) {
		// unchanged
	}
};
```

Same reasoning as the permalink rule. It belongs to the folder, not to each page, and any single page can still override it with its own `layout` in front matter. Set it once, forget it, break the rule where you need to.

Restart the dev server and look again. The words are the same, but there is a document around them now, and a title in the browser tab you did not write.

---

## Add the stylesheet

Baseline compiles two entry points, one for CSS and one for JS, both named `index`. That sounds restrictive until you notice that `@import` and `import` still reach everything else from there.

First a small piece of housekeeping, and it is worth doing before the files rather than after. Create `src/assets/assets.11tydata.js`:

```js
export default {
	eleventyExcludeFromCollections: true
};
```

Baseline registers CSS and JS as template formats so it can compile them, which technically makes them pages. Without this file they turn up in `collections.all`, and `index.css` appears in the list of links on your homepage. One line, one folder, problem gone.

Now the stylesheet, `src/assets/css/index.css`:

```css
body {
	font-family: system-ui, sans-serif;
	margin: 0;
	padding: 2rem;
	line-height: 1.5;
	color: #1f2937;
	background: #f8fafc;
}

h1 {
	margin-bottom: 0.5rem;
}
```

And `src/assets/js/index.js`, which the site does not need but the settings file has been promising since page three:

```js
document.addEventListener('DOMContentLoaded', () => {
	console.log('Howdy!');
});
```

Both compile into `dist/assets/`, mirroring the folders they came from, so `src/assets/css/index.css` is served at `/assets/css/index.css`. That is the path already sitting in `settings.head.link`, which is why the stylesheet loads without you adding a `<link>` anywhere. Compiling and loading are two separate jobs. Baseline only does the first.

Reload once more and the page has a face.

The site is finished, in the sense that everything it needs now exists. What is left is knowing what happens when you run it for real.
