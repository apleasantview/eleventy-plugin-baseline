Baseline has an opinion about where things live: `src/` for what you write, `dist/` for what gets built, and a handful of folders in between that it knows how to find without being told. That opinion is the reason you can skip most of the configuration later, and it's the reason this page comes first.

So we build the shape by hand before installing anything. It takes a minute, and afterwards every file in the rest of the tutorial has an obvious place to go.

---

## Make the folder

```bash
mkdir simple-baseline-site
cd simple-baseline-site
```

Everything from here happens inside that folder.

---

## Lay out the directories

Here is the whole structure. Nothing in it is a placeholder; every folder gets used before the tutorial is over.

```text
simple-baseline-site/
  src/
    _data/              # site identity lives here
    _includes/
      layouts/          # the shell your pages render into
    assets/
      css/              # one CSS entry point
      js/               # one JS entry point
    content/
      pages/            # your Markdown
    static/             # copied to the site root untouched
```

One command makes all of it:

```bash
mkdir -p src/_data src/_includes/layouts src/assets/css src/assets/js src/content/pages src/static
```

That's bash. If your shell doesn't take `-p`, make them by hand from the tree above.

Half of those names are Baseline's and half are yours. Worth knowing which is which now, because it saves an argument later:

- `_data`, `_includes`, `assets` and `static` are Baseline's. It ships a directory configuration that names them, and renaming one means telling Eleventy about it yourself.
- `content/` and anything under it is yours. Eleventy renders what it finds in `src/`, so the arrangement inside `content/` is a filing decision, not a technical one. `pages/` is just the first drawer.
- `dist/` is missing on purpose. It appears the first time you build.

`static/` is the one oddity. On disk it's `static/`, but in templates and config Baseline calls it `public`, which is the name most site generators use. Two names, one folder. It only matters when you go looking for it in the [[project-structure | project structure]] page.

## Keep the generated files out of git

If you're tracking this in git, add a `.gitignore` at the project root:

```text
node_modules/
dist/
.env
```

The first two are rebuilt from what you commit, so there's nothing to gain by keeping them. The third doesn't exist yet: `.env` arrives on the next page and holds the values that differ between your laptop and the live site. Ignoring it now means never having to remember to.

Not using git? Skip the file. Nothing else in the tutorial depends on it.

## Add the package file

Now the folder can become a project.

```bash
npm init -y
```

That writes a `package.json` with defaults. Open it and add two things:

```json
{
	"name": "simple-baseline-site",
	"type": "module",
	"scripts": {
		"start": "rimraf dist/ && npx @11ty/eleventy --serve",
		"build": "rimraf dist/ && cross-env ELEVENTY_ENV=production npx @11ty/eleventy"
	}
}
```

`"type": "module"` tells Node that the `.js` files in this project are ES modules, written with `import` and `export`. Baseline is ESM and so is your config, and without this line Node reads `eleventy.config.js` as an older-style CommonJS file and stops at the first `import` with a message about not being able to use import statements outside a module. It's a one-line fix to a confusing error, so it's worth setting before you can trip over it.

The two scripts are the only commands you need for the rest of the tutorial: `npm start` for local development, `npm run build` for the production build. Both clear `dist/` first, for a reason that gets its own aside once you have something to build.

Both scripts also lean on two small helpers you haven't installed yet. That's the last step on this page.

---

## Install the packages

Three commands, so you can see what each one is for.

```bash
npm install @11ty/eleventy @11ty/eleventy-img
```

Eleventy itself, and the image library. Baseline names both as peer dependencies: they're the two packages your project uses directly as well, so they belong in your `package.json` rather than hidden inside the plugin's.

```bash
npm install rimraf cross-env
```

The helpers from the scripts above. `rimraf` deletes `dist/` the same way on every operating system, and `cross-env` sets `ELEVENTY_ENV=production` for one command on Windows too, where a bare `NAME=value` prefix isn't understood.

```bash
npm install @apleasantview/eleventy-plugin-baseline
```

And Baseline. It arrives with everything else it needs already inside it, PostCSS and esbuild included, which is why this is the shortest line of the three.

Nothing runs yet. There's no config telling Eleventy about Baseline, and no content to render. Both arrive next.
