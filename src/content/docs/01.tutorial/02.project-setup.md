Baseline has an opinion about where things live. `src/` for what you write, `dist/` for what gets built, and a handful of folders in between that it finds by name.

Build that shape first and every file in the rest of the tutorial has an obvious place to go.

```text
simple-baseline-site/
  src/
    _data/              # site identity lives here
    _includes/
      layouts/          # the shell your pages render into
    assets/
      css/              # one CSS entry point
      js/               # one JS entry point
    content/
      pages/            # your Markdown content
    static/             # copied to the site root untouched
```

## Make the folders

Let's start by creating the project folder and `cd` into it:

```bash
mkdir simple-baseline-site
cd simple-baseline-site
```

Everything after this happens in there. What goes inside splits in two: the names Baseline expects, and the ones held by convention.

`_data`, `_includes`, `assets` and `static` are Baseline's. It finds them by looking, so renaming one means telling Eleventy about it yourself.

`static/` is the odd one of the four: on disk it stays `static/`, but in templates and config Baseline calls it `public`, the name most generators use. Two names, one folder. It only matters the day you go looking for it in [[project-structure | project structure]].

`content/` and `pages/` are named that way by convention. Eleventy renders whatever it finds in `src/`, so the naming is your call in the end, but the conventions are worth keeping while you learn where things go.

Here's one Bash command to make them all at once:

```bash
mkdir -p src/_data src/_includes/layouts src/assets/css src/assets/js src/content/pages src/static
```

If your shell doesn't take `-p`, make them by hand from the tree above.

The `dist/` folder is missing on purpose. It appears the first time you build your site.

## Keep the generated files out of git

If you are tracking this in git, add a `.gitignore` at the project root. Not using git? Skip the file. Nothing else in the tutorial depends on it.

```text
node_modules/
dist/
temp/
.env
```

`node_modules/`, `dist/` and `.env` are the usual suspects: two are rebuilt from what you commit, and the third arrives on the next page holding the values that differ between your laptop and the live site. `temp/` is a bonus folder to put stuff in.

## Add the package file

Now the folder can become a project. Generate a standard `package.json` file:

```bash
npm init -y
```

Then add `"type": "module"`, which tells Node that the `.js` files here are ES modules, plus the two scripts the rest of the tutorial needs.

```diff-json
{
	"name": "simple-baseline-site",
	"version": "1.0.0",
+	"type": "module",
	"scripts": {
-		"test": "echo \"Error: no test specified\" && exit 1"
+		"start": "rimraf dist/ && npx @11ty/eleventy --serve",
+		"build": "rimraf dist/ && cross-env ELEVENTY_ENV=production npx @11ty/eleventy"
	}
}
```

`npm init` writes a handful of other keys as well, `description`, `main`, `keywords`, `author` and `license`. Leave them where they are; nothing in this tutorial reads any of them.

Baseline is ESM, and so is the config you are about to write. Without that line Node reads `eleventy.config.js` as a CommonJS file and stops at the first `import`.

Both scripts lean on two small helpers, installed in the last step on this page.

## Install the packages

```bash
npm install @11ty/eleventy @11ty/eleventy-img # Eleventy and the image library
npm install rimraf cross-env # the two script helpers
npm install @apleasantview/eleventy-plugin-baseline # and Baseline itself
```

Eleventy and the image library come first: Baseline names both as peer dependencies, so they belong in your `package.json` rather than inside the plugin. Then the two helpers the scripts lean on, `rimraf` to delete `dist/` and `cross-env` to set environment variables, both of them the same way on every operating system. Baseline comes last, and brings everything else it needs with it.

Nothing runs yet. There is no config telling Eleventy about Baseline, and nothing to render. Both arrive next.
