Two fixes, and both of them killed builds.

The first is the one worth apologising for. Adding Baseline to a project that leaves `htmlTemplateEngine` at Eleventy's default ended the build before it wrote a single file. That default is what you get from the official Eleventy quickstart, so installing Baseline on a fresh project and registering it as a plugin was enough to hit it. The error named a template inside Baseline, which made it read like Baseline was broken rather than like one setting was missing. If that happened to you, it was not something you did.

The second: `settings.url: '/'` threw `TypeError: Invalid URL` partway through rendering, instead of warning and leaving canonical, Open Graph and JSON-LD out as Baseline says it will.

Nothing breaks in this release. If you are on `next.48` and worked around either of these, the workaround is now unnecessary but harmless.

---

## Fixed

- **Baseline no longer requires its own `config` export to build.** Baseline registers a few templates of its own, for the sitemap and the navigator debug page. Their contents are Nunjucks, Eleventy's default engine for `.html` is Liquid, and Liquid cannot parse Nunjucks comments. The build stopped with `illegal tag syntax` and wrote nothing.

  Baseline's `config` export sets `htmlTemplateEngine: 'njk'`, so a project spreading that config never saw this, which is why it survived as long as it did. Baseline's own templates now declare their engine per template, which also means Baseline no longer has an opinion about yours. A Liquid project is a Liquid project.

  - _Symptom, before: `Having trouble rendering liquid template ./_baseline/sitemap-core.html`, zero files written. If you added `htmlTemplateEngine: 'njk'` to work around it, you can keep it or drop it; it changes nothing now._

- **A `settings.url` that is not an absolute URL warns instead of throwing.** Setting it to `/`, or to a bare domain with no scheme, killed the render with `TypeError: Invalid URL`.

  Baseline validated this value in one place and said so out loud, then read it unvalidated in another and handed it to the URL builders. Both halves now resolve it the same way, and the helpers that build absolute URLs return nothing on a base they cannot resolve rather than throwing.

  - _Symptom: the documented behaviour, which is a warning naming the value you set, and canonical, Open Graph and JSON-LD left out. The build finishes._

  - _If you want relative output, leave `settings.url` out entirely rather than setting it to `/`. Both give you the same thing, and the empty case is the one the docs describe._

## Internal

- The published entry point has a test. Nothing previously asserted that the package resolves by name, that both its exports exist, or that the `exports` map still keeps internals unreachable. All three are checked now, so widening that map stops being a silent change.

- Both fixes landed with tests at the unit that failed, rather than only at the build that noticed.
